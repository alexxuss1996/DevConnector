# Storybook + Button + Stories Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a runnable Storybook to `apps/web` with a hand-written `button.tsx` wrapper, a rich validated `ExampleForm`, and one `*.stories.tsx` for every file in `src/components/ui/`.

**Architecture:** Storybook 9 + `@storybook/nextjs` (single Next-native toolchain) in `apps/web` only; Chakra decorator (`ChakraProvider` + `ColorModeProvider`, no `NuqsAdapter`); CSF3 stories co-located with sources; `ExampleForm` built on the already-installed `react-hook-form` + `@hookform/resolvers`, adding only `zod`.

**Tech Stack:** Storybook 9, `@storybook/nextjs`, `@storybook/addon-essentials`, `@storybook/addon-a11y`, Chakra UI 3.37, React 19.3, Next 16.3.5, react-hook-form 7, zod 3/4, pnpm workspaces.

**Spec:** `docs/superpowers/specs/2026-09-25-storybook-design.md`

## Global Constraints

- Package manager is `pnpm@11.22.0`; run all app-scoped commands from repo root as `pnpm --filter web …` (app dir: `apps/web`).
- `npm run lint` = `eslint --max-warnings 0` — zero warnings allowed; never write `interface X extends Y {}` (use `type X = Y`), except when tsc `TS2742` forces an interface (as with `link-button.tsx`), in which case keep the interface + `// eslint-disable-next-line @typescript-eslint/no-empty-object-type`.
- `npm run check-types` (`next typegen && tsc --noEmit`) must stay green; annotate re-exports with `: typeof ChakraX.Y` whenever tsc reports `TS2742`.
- Per `apps/web/AGENTS.md`, read the relevant guide in `apps/web/node_modules/next/dist/docs/` before writing any Next-related code.
- Verify Chakra prop/variant names against the installed types in `apps/web/node_modules/@chakra-ui/react/dist/types/` — never rely on memory for recipe props. Chakra v3 renames: `colorPalette` (not `colorScheme`), `loading` (not `isLoading`), `disabled` (not `isDisabled`), icons as children (not `leftIcon`).
- The working tree has unrelated uncommitted changes — every commit in this plan stages ONLY the task's own files (`git add <paths>`), never `git add -A`.
- No visual-regression tests in v1; stories only.

## Review Focus

- `toaster.tsx` exports a module singleton (`toaster`) — a story that fires toasts must render its own `<Toaster />` and not leak toasts between stories; expect the reviewer to fire two toasts in a row and check both render and dismiss.
- Stories must use uncontrolled inputs (`defaultValue`/`defaultChecked`/`defaultOpen`) unless a story owns `useState` — a reasonable person typing in an input story expects the text to appear.
- Overlay stories (Dialog/Drawer/Popover/Menu/HoverCard) trap focus and portal — expect the reviewer to open each and press Escape to close it inside the Storybook iframe.
- `NumberInput`/`StepperInput` parse numeric strings — expect empty-string clearing to not crash the story (pass `defaultValue`, no controlled `value` without `onChange`).
- `ColorModeProvider` wraps every story via the preview decorator — expect the reviewer to toggle light/dark (toolbar or `ColorModeButton` story) and see the change apply.

## File Structure

- Create: `apps/web/.storybook/main.ts` (Task 1), `apps/web/.storybook/preview.tsx` (Task 1), `apps/web/src/components/ui/button.tsx` (Task 2), `apps/web/src/components/forms/ExampleForm.tsx` (Task 6), 43× `*.stories.tsx` co-located with sources (Tasks 2–6).
- Modify: `apps/web/package.json` (storybook scripts + zod dep; Task 1 & 6).
- Delete: example stories generated by `storybook init` (`Button.stories.tsx` etc. under `src/stories/` if created).
- Skip: `src/components/ui/provider.tsx` (needs Next app-router `NuqsAdapter`; the preview decorator covers providers instead).

```tsx
"use client";

import { Input, Textarea } from "@chakra-ui/react";
import { zodResolver } from "@hookform/resolvers/zod";
import * as React from "react";
import { Controller, useForm } from "react-hook-form";
import { z } from "zod";
import { Button } from "../ui/button";
import { Checkbox } from "../ui/checkbox";
import { Field } from "../ui/field";
import { NativeSelectField, NativeSelectRoot } from "../ui/native-select";
import { NumberInputField, NumberInputRoot } from "../ui/number-input";
import { PasswordInput } from "../ui/password-input";
import { Radio, RadioGroup } from "../ui/radio";
import { Switch } from "../ui/switch";
import { TagsInputControl, TagsInputRoot } from "../ui/tags-input";

const schema = z.object({
  name: z.string().min(2, "Name needs at least 2 characters."),
  email: z.string().email("Enter a valid email address."),
  password: z.string().min(8, "Password needs at least 8 characters."),
  age: z.coerce.number().int().min(13, "Must be 13 or older."),
  bio: z.string().max(280, "Bio must be 280 characters or less.").optional(),
  role: z.enum(["frontend", "backend", "fullstack"], {
    message: "Pick a role.",
  }),
  gender: z.enum(["she", "he", "they"], { message: "Pick an option." }),
  birthdate: z.string().min(1, "Pick a birthdate."),
  notify: z.boolean(),
  terms: z.literal(true, {
    message: "You must accept the terms.",
  }),
  tags: z.array(z.string()).min(1, "Add at least one tag."),
});

export type ExampleFormValues = z.infer<typeof schema>;

export function ExampleForm({
  onSubmit,
}: {
  onSubmit: (values: ExampleFormValues) => void;
}) {
  const {
    register,
    control,
    handleSubmit,
    formState: { errors, isSubmitting },
  } = useForm<ExampleFormValues>({
    resolver: zodResolver(schema),
    defaultValues: {
      name: "",
      email: "",
      password: "",
      bio: "",
      role: "frontend",
      notify: true,
      tags: ["react"],
    },
  });

  return (
    <form
      onSubmit={handleSubmit(onSubmit)}
      style={{ display: "grid", gap: 16, maxWidth: 480 }}
    >
      <Field
        label="Name"
        invalid={!!errors.name}
        errorText={errors.name?.message}
      >
        <Input {...register("name")} placeholder="Alex" />
      </Field>
      <Field
        label="Email"
        invalid={!!errors.email}
        errorText={errors.email?.message}
      >
        <Input {...register("email")} placeholder="you@example.com" />
      </Field>
      <Field
        label="Password"
        invalid={!!errors.password}
        errorText={errors.password?.message}
      >
        <PasswordInput {...register("password")} />
      </Field>
      <Field label="Age" invalid={!!errors.age} errorText={errors.age?.message}>
        <NumberInputRoot>
          <NumberInputField {...register("age")} />
        </NumberInputRoot>
      </Field>
      <Field label="Bio" helperText="Up to 280 characters.">
        <Textarea {...register("bio")} placeholder="I build things." />
      </Field>
      <Field label="Role" invalid={!!errors.role} errorText={errors.role?.message}>
        <NativeSelectRoot>
          <NativeSelectField {...register("role")}>
            <option value="frontend">Frontend</option>
            <option value="backend">Backend</option>
            <option value="fullstack">Fullstack</option>
          </NativeSelectField>
        </NativeSelectRoot>
      </Field>
      <Field
        label="Gender"
        invalid={!!errors.gender}
        errorText={errors.gender?.message}
      >
        <Controller
          name="gender"
          control={control}
          render={({ field }) => (
            <RadioGroup {...field}>
              <Radio value="she">She</Radio>
              <Radio value="he">He</Radio>
              <Radio value="they">They</Radio>
            </RadioGroup>
          )}
        />
      </Field>
      <Field
        label="Birthdate"
        invalid={!!errors.birthdate}
        errorText={errors.birthdate?.message}
      >
        <Input type="date" {...register("birthdate")} />
      </Field>
      <Controller
        name="notify"
        control={control}
        render={({ field }) => (
          <Switch checked={field.value} onCheckedChange={field.onChange}>
            Email notifications
          </Switch>
        )}
      />
      <Controller
        name="terms"
        control={control}
        render={({ field }) => (
          <Checkbox checked={field.value === true} onCheckedChange={field.onChange}>
            I accept the terms
          </Checkbox>
        )}
      />
      {errors.terms && <p style={{ color: "red" }}>{errors.terms.message}</p>}
      <Field label="Tags" invalid={!!errors.tags} errorText={errors.tags?.message}>
        <Controller
          name="tags"
          control={control}
          render={({ field }) => (
            <TagsInputRoot value={field.value} onValueChange={field.onChange}>
              <TagsInputControl clearable />
            </TagsInputRoot>
          )}
        />
      </Field>
      <Button type="submit" loading={isSubmitting} colorPalette="blue">
        Create profile
      </Button>
    </form>
  );
}
```

Adjust the `Controller` bindings to the real prop names; uncontrolled `register` usage stays as above.)
